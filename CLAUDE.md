# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

See `AGENTS.md` for all project conventions, architecture, build commands, code style, debugging workflow, and working-with-AI-agents rules. Everything there applies here too.

## Claude-Specific Notes

- **Presenting options**: The popup carries the choices; prose carries the reasoning. Whenever there are 2+ choices, `AskUserQuestion` is what asks — never a plain-text list answered by replying "A", and never the alternatives rendered as a menu in the message as well. But say in the message first what each direction costs and which you recommend: compressing the tradeoffs into the widget's own option descriptions puts them in front of the user at the moment they are choosing, with no way to compare them side by side. The test is whether the choice could be answered in the popup without the prose. If the choosing happens in the prose, it has gone too far.
- **Attribution**: Do not add `🤖 Generated with Claude Code` or similar footers to PR descriptions, issue bodies, or commit messages.
- **Hooks** (`.claude/settings.json`, scripts in `.claude/hooks/`): when a reply ends with changes to anything the compiler reads, `build-on-stop.ps1` builds what the change can affect before handing back, and a build that is not clean — errors *or* warnings, since zero warnings is the standard — blocks the stop once with the diagnostics. The test project plus Core always builds (seconds, and it is the one that gets missed: building the app project does not compile `tests/`, and `dotnet test` filtered for failures hides warnings entirely); the Android TFM builds when something under `src/AniSprinkles/` changed, `AndroidManifest.xml` and the Android resource XML included — aapt2 compiles those, and a bad resource reference fails the build as hard as bad C# does; the `-p:CiBuild=true` variant builds when a `#if CI` file or a fixture under `Fixtures/AniList/` changed, because nothing else compiles those blocks. A **build input** — a `.csproj`, `.props`, `.targets`, `.editorconfig`, `global.json` or `nuget.config` — forces all three, because which projects it reaches is not worth modelling: everything references Core, and the root `.editorconfig` carries analyzer severity for every file in every project. It skips in about half a second when the sources are unchanged since the last clean run (fingerprint in the git-ignored `.claude/hooks/.last-build`), and with no fingerprint yet — a fresh worktree — it asks git what differs from `HEAD` rather than building all three blind, which costs four and a half minutes against three seconds for a Core-only change. It lets the second stop through so a build it cannot fix is reported rather than looped on. It runs no tests — that is `/ani-review`'s job. Switch it off with `/hooks`.
