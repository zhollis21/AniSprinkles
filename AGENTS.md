## Architecture

- **.NET MAUI Android-only** app (`net10.0-android`; `SupportedOSPlatformVersion` 31.0). App ID: `com.RainbowSprinkles.AniSprinkles`.
- **Two sibling projects under `src/`** (#62):
  - `src/AniSprinkles.Core/` (plain `net10.0`) — `Models/`, `Utilities/`, non-platform `Services/`, `Services/Abstractions/`, `Converters/`, `Icons/`, and **all** `PageModels/`. The plain TFM is the point: it is what lets `tests/AniSprinkles.UnitTests/` project-reference the page models instead of link-compiling source files.
  - `src/AniSprinkles/` (`net10.0-android`) — everything needing MAUI UI, Android, or the icon font: `Pages/`, `Views/`, `Behaviors/`, `Platforms/`, `MauiProgram.cs`, `AuthService`, `AiringNotificationService`, the CI stubs, the Android fault-injection receiver, and the `Services/Maui/` adapters implementing Core's abstractions.

  Keep them siblings. Nesting one project inside another's directory makes the outer project's default globs sweep up the inner project's sources *and* its `obj/` generated assembly attributes, which fails the build in a way that reads as a code error.
- **Core references neither `CommunityToolkit.Maui` nor `IconFont.Maui.FluentIcons`**, deliberately. Popups, snackbars and toasts go through `IDialogService` / `IUserFeedback`; leaving the package out is what stops that seam eroding. Icon glyphs are mirrored into `Core/Icons/Glyphs.cs` (generated by `tools/generate-glyphs.cs`, validated against the real package by `IconGlyphReferenceTests`) because the package ships platform TFMs only.
- **MVVM** via CommunityToolkit.Mvvm: PageModels extend `ObservableObject`, use `[ObservableProperty]`, `[RelayCommand]`, `[NotifyPropertyChangedFor]`. The four details page models extend `DetailsPageModelBase<TEntity>` instead, which supplies the shared load/error/retry/favourite/external-link spine — see `/project-architecture`. Shell bottom-tab navigation (`library` with `anime`/`manga` sub-tabs, `discover`, `search`, `feed`, `settings`) with programmatic `media-details`, `staff-details`, `character-details`, `studio-details`, and `media-browse` routes. PageModels navigate through the injected `INavigationService` (routes + lightweight query params — never full objects); persist state via the injected `IPreferences`; marshal pool-thread continuations back to the UI via the injected `IDispatcher`; read app metadata via the injected `IAppInfo`. View-facing UX calls go through Core abstractions too — `IDialogService` for confirmations, prompts and the bottom-sheet pickers, `IUserFeedback` for snackbars and toasts, `IExternalBrowser` for "view on AniList" — each implemented in `src/AniSprinkles/Services/Maui/`. A PageModel must not reach `Shell.Current`, a popup type, or an Essentials static directly: `Shell.Current` and `Application.Current` return **null** off-device rather than throwing, so such a call silently no-ops and its test passes without exercising anything. The one exception is `HapticFeedback.Default.Perform` in `EntryActionCoordinator` — it returns nothing, has no observable effect to assert, and is already wrapped in a swallowing `catch`, so a seam would buy nothing.
- **DI**: Services and tab PageModels (`AnimeLibraryPageModel` and `MangaLibraryPageModel` — two singletons over one parameterized `MediaListPageModel`, #12 — plus `DiscoverPageModel`, `SearchPageModel`, `SettingsPageModel`) are singleton. All Pages and details PageModels (`MediaDetailsPageModel`, `StaffDetailsPageModel`, `CharacterDetailsPageModel`, `StudioDetailsPageModel`, `MediaBrowsePageModel`) are transient. See `/project-architecture` for the full DI table and page patterns.
- **Services**: `AuthService` (OAuth + SecureStorage), `AniListClient` (GraphQL + viewer ID cache), `ErrorReportService` (Sentry + `ILogger`), `SensitiveText` / `SentryScrubber` (bearer-token redaction), `FileLoggerProvider` (rotating async file log, Debug = 1 MB × 3 / Release = 256 KB × 3), `AndroidLogcatLoggerProvider` (bridges `ILogger` → `adb logcat` on Android), `LoggingHandler` (HTTP DelegatingHandler), `AiringNotificationService` (WorkManager periodic check), `DiagnosticsLogBuffer` / `DiagnosticsSessionLog` / `DiagnosticsSessionFlusher` / `DiagnosticsReportBuilder` / `SentryDiagnosticsSink` + `DiagnosticsReportCoordinator` (user-sent diagnostic reports, #112). See `/airing-notifications` for the notification subsystem.
- **Global usings** (`GlobalUsings.cs`): `Models`, `PageModels`, `Pages`, `Services`, `IconFont.Maui.FluentIcons`. `Converters` and `Utilities` require explicit `using`.
- **Key NuGet packages**: `Microsoft.Maui.Controls`, `CommunityToolkit.Mvvm`, `CommunityToolkit.Maui`, `Sentry.Maui`, `Syncfusion.Maui.Toolkit`, `IconFont.Maui.FluentIcons`.

## Integration Points (AniList API)

- **Endpoint**: `https://graphql.anilist.co`. Auth: OAuth implicit grant, redirect URI `anisprinkles://auth`, token in `SecureStorage` keys `anilist_access_token` and `anilist_access_token_expires_at`.
- **Every request must carry a `Referer: https://anilist.co/` header** (#160). AniList rejects any request that has neither a `Referer` nor an `Authorization` header with HTTP 403 — and the body says *"The AniList API has been temporarily disabled due to severe stability issues"*, which `AniListErrorClassifier` reads as an outage marker. So the failure does not present as "we sent a bad request", it presents as a false **"AniList is Down"** banner while AniList is serving other clients normally. A token satisfies the same filter, but cannot be the whole answer: signed-out browsing (Discover, Search, every details page) has no token by definition, and `AiringScheduleFetcher` has none by design. The header is set in **two** places — `AniListClient.SendAsyncCore` and `AiringScheduleFetcher.Fetch` — because the worker deliberately bypasses the client; if a third path to AniList is ever added, it needs its own. `AniListRateLimitHandler` rebuilds requests from a `RequestTemplate` on retry and copies request headers across, so retries keep it; there is a test pinning that.
- **Viewer ID caching**: lightweight `Viewer { id }` query cached by token string; invalidates on re-auth.
- **Person names come from `userPreferred`, never `full`** (#130). AniList resolves `userPreferred` server-side against the viewer's Staff Name Language, and it is script-aware where `full` is not: measured on a real account set to `ROMAJI`, `full` returned "Bairstow Caitlyn" for a Latin-script name while `userPreferred` returned "Caitlyn Bairstow" (a Japanese name flipped in both). All eleven `name { ... }` selections request it, and `StaffNameFormat` falls back to `full` only when it is absent. The cost is that a change needs a refetch rather than a re-projection — see `InvalidateEntityCache` under Caching.
- **Operations**: `Viewer`, `ViewerFull`, `MediaListCollection`, `Media`, `SaveMediaListEntry`, `DeleteMediaListEntry`, `UpdateUser`, `AiringSchedule` / `Staff` / `Character` / `Studio` / `Search` / `DiscoverSections` / `BrowseAnime` (the latter seven work without auth; the browse/search trio sends the token when present so `mediaListEntry` fills in the viewer's list status). `DiscoverSections` batches every Discover row's first page (+ `pageInfo`) into ONE aliased request — keep it that way (rate-limit budget); scrolling a row past its seed pages it through `BrowseAnime`, one request per row-page, via the shared `DiscoverSectionFetch`.
- **`Media(id:)` is type-agnostic, and `type: ANIME` was ours** (#12). Media ids are unique across anime and manga, so the `type` argument is only a filter — `Media(id: 30002)` resolves Berserk while `Media(id: 30002, type: ANIME)` returns 404. Dropping that pin from `MediaQuery` and the three per-section paging queries is what made the details page serve both. `Search` now takes `$type` as a variable, and **an absent `type` searches both** — passing `type: null` explicitly returns an empty list, so the All pill relies on `JsonIgnoreCondition.WhenWritingNull` dropping the variable rather than sending a JSON null; **Discover and `BrowseAnime` are still anime-only on purpose** — `MediaSeason`/`seasonYear` don't apply to manga, so the Airing and Upcoming rows have no manga analogue.
- **Manga progress has two counters and one active unit** (#12). AniList keeps `progress` (chapters) and `progressVolumes` as fully independent fields, relates neither to the other nor to status, and has no auto-complete setting — which counter drives the UI is entirely a client decision. `MediaListEntry.UsesVolumeProgress` picks it, matching AniHyou: chapters unless the entry has volume progress *and* no chapter progress. Everything reads `ActiveProgress` / `ActiveProgressTotal` / `ActiveProgressUnit` rather than assuming episodes, and wording comes from `MediaListVocabulary` so "Watching"/"Reading" and "Episodes"/"Chapters"/"Volumes" can't drift between the details page, the status picker and the action menu. The unit is **derived**, so any caller that writes progress and may need to undo it must capture the unit first and revert through `SetProgressFor` — `SetActiveProgress` could otherwise land on the other field.
- **AniList publishes no chapter schedule.** `chapters` and `volumes` are null for *every* RELEASING series (verified across One Piece, Berserk, Dandadan, Sakamoto Days), and there is no `nextAiringEpisode` equivalent to fall back on the way an airing anime has. So an ongoing manga has no cap, no progress bar, no "chapters behind" and no completion prompt — that is the common case, not an edge one.
- **Rate limiting**: `AniListRateLimitHandler` (a `DelegatingHandler`) serializes all requests, reads `X-RateLimit-Remaining`/`X-RateLimit-Reset` for adaptive spacing, and does bounded `Retry-After`-aware retry on 429 (surfacing `ApiErrorKind.RateLimited` when the wait exceeds the cap or retries are exhausted).
- **Transient retry**: `AniListClient.SendAsync` retries once (short delay) on plausibly transient failures — `Network`, `Authentication` (e.g. AniList's sporadic `400 "Invalid token"` on a valid token), and `Unknown` — and **not** `RateLimited` (owned by the handler above), `NotFound`, or `ServiceOutage`. A recovered blip stays a `Warning` breadcrumb and isn't reported to the outage tracker.
- **`NotFound` is no longer a dead end (#158).** It is still excluded from the *automatic* retry above, but the error card now offers Retry and produces a report like every other failure — it used to get neither, and `ErrorStateView` gates Copy/Share on that report string, so the error a user can least explain was the only one they could neither retry nor send. The classifier now matches AniList's `"Not Found."` message **exactly** rather than as a substring anywhere in server text (`AniListErrorClassifier.IsNotFoundMessage`); a substring hit turned any transient failure containing those two words into a permanent, silent dead end. One consequence to know about: `NotFound` now reaches Sentry, deliberately, because the frequency data is what was missing. Fingerprint it down if it proves noisy.
- **Caching**: `CachingAniListClient` decorates `IAniListClient`, caching character/staff/studio reads for the session and coalescing concurrent same-key fetches. `InvalidateEntityCache()` drops them; `SettingsPageModel` calls it when Staff Name Language changes (#130), because names render from `userPreferred` — resolved server-side against that setting, so cached reads hold a stale rendering. Invalidate-only, no refetch: pages reload as the user navigates to them. Other reads (lists, search, media, discover/browse) pass through — broader caching is a planned follow-up. Discover sections have their own ~20-minute TTL cache inside the singleton `DiscoverPageModel` (invalidated by pull-to-refresh, an adult-toggle flip, or an auth change) because the rows carry viewer-relative `mediaListEntry` state.
- **On Android a cancelled request is not an `OperationCanceledException`.** `AndroidMessageHandler` disconnects the underlying `HttpURLConnection`, so the read already in flight fails with `Java.Net.SocketException("Socket closed")` and reaches managed code as a **`System.Net.WebException`** — a type no `catch (OperationCanceledException)` in the app matches. Both HTTP boundaries therefore consult the *token*, not the exception type — but **not the same token**, and the difference is the whole trick:
  - `AniListClient.SendAsyncCore` holds the **caller's** token and calls `ThrowIfCancellationRequested()` before classifying, so a superseded search or a page left mid-load abandons quietly while an uncancelled socket drop still classifies as `Network`.
  - `LoggingHandler` sits *inside* the pipeline, where the only token in scope is HttpClient's **linked** one — cancelled by `HttpClient.Timeout` as well as by the caller. Treating that as cancellation files a 100-second timeout away as a breadcrumb, hiding the exact failure the handler exists to report. So `AniListClient` records its own token on `request.Options` under `LoggingHandler.CallerCancellationToken`, and the handler reads that; with no token recorded it logs `Error`, because a redundant Sentry event is cheaper than a missing one.
  - `AniListRateLimitHandler`'s `RequestTemplate` copies `Options` across when it rebuilds the message (which it does on **every** send, not just retries), or none of the above would reach the handlers below it.

  Left unhandled, a user typing through the search debounce got a "Search failed" snackbar and an error report per keystroke.
- **HttpClient**: singleton; pipeline is `AniListRateLimitHandler` → `LoggingHandler` → `HttpClientHandler`. Bearer token and `Referer` attached per-request in `AniListClient.SendAsyncCore`. The "public query, no auth needed" pattern is gone (#160): operations that do not *require* a token still send one when the app holds one, because withholding a credential we already have buys nothing and costs the only other thing AniList's filter accepts.

- **CI**: GitHub Actions `android-release.yml` triggers on Release publication (or manual `workflow_dispatch`). `promote-release.yml` promotes between Play Console tracks (internal → alpha → beta → production).
- **Version scheme**: `ApplicationDisplayVersion` from release tag semver (`vX.Y.Z` → `X.Y.Z`); `ApplicationVersion` (versionCode) from `YYMMDDNNN` (date + run_number mod 1000).
- **Unit tests** — `tests/AniSprinkles.UnitTests/` (xUnit, `net10.0`, NSubstitute). Project-references `src/AniSprinkles.Core/`; there are no link-compile globs any more (#62). Covers pure algorithms, PageModel state machines, and repo-level file validation (`.xaml` well-formedness, icon-glyph resolution). Test doubles live in `Fakes/`. `tests/AniSprinkles.UITests/` is still a scaffold for future device tests.
  - **Watch what throws vs. what returns null off-device.** On the plain `net10.0` TFM, `Shell.Current` and `Application.Current` are `null` (a quiet no-op that reads as a passing test), while `Preferences`, `SecureStorage`, `MainThread`, `AppInfo` and `Browser` throw `NotImplementedInReferenceAssemblyException`. Anything a test needs to reach must be injected — `SecureStorage` behind `ISecureTokenStorage` (#119) is the most recent example.
  - **Fixing a bug starts with a failing test.** Write the test that reproduces the reported behaviour, run it, and watch it fail *for the reason you expect*, before touching the fix. A test written after the fix proves the code passes its own description — it does not prove it would have caught the bug, and a test that never failed is indistinguishable from one asserting the wrong thing. If the bug genuinely cannot be reached from `tests/` (see what throws off-device, above), say so explicitly and verify on device via `/run-anisprinkles` instead — don't quietly skip the step.
  - `AppSettings.Load/Save/Clear/SyncFromViewer` go through the injectable `AppSettings.Storage` seam (#121), so paths ending in them — a successful `SettingsPageModel.LoadAsync`, for instance — are testable. `TestDataBuilder.ResetAppSettings()` installs a `FakePreferences` and returns it.
  - Test classes that write to the process-wide `AppSettings` statics must join the `AppSettings` collection (`AppSettingsCollection.Name`) so they do not run in parallel. That includes `AppSettings.Storage`.

## CI Stubs (`-p:CiBuild=true`)

Passing `-p:CiBuild=true` in a **Debug** build appends `CI` to `DefineConstants`. This activates `#if CI` blocks that swap in stub services. Do **not** use `-p:CiBuild=true` with `-c Release`; the project file only supports this for Debug builds, and Release builds error out.

- `CIAuthService` (`src/AniSprinkles/Services/CI/`) — always returns `"ci-stub-token"`; app appears authenticated
- `CIAniListClient` (`src/AniSprinkles/Services/CI/`) — returns hardcoded anime list, user profile, and details-page fixtures. It **honours the `isAdult` filter contract** (`false` = SFW only, `true` = 18+ only, `null` = unfiltered) rather than ignoring it, because of the canary below.
  - **Adult-content canary.** One fixture is flagged `IsAdult` and titled `18PLUS CANARY - FILTER FAILED` (`StubData.AdultCanaryTitle`), seeded into both the stub list and the browse/search results. It carries no adult content — the title is a marker and it has no cover image. The stub viewer leaves `DisplayAdultContent` off and nothing in CI turns it on, so every surface must filter it out; `ci-build-and-preview.yml` dumps the UI after each capture and **fails the run** if it renders. That wording is load-bearing: the `ui-screenshots` job was `continue-on-error: true` until now, so the canary failed its job while the run still concluded success — a gate that detects everything and blocks nothing. Keep that job blocking; the flaky-capture paths are already `::warning::` and don't need it. Before this, the adult filter was never exercised end to end — `DiscoverSectionFetch`, the browse/search `isAdult` argument and `MediaListSectionsMerger` could all have broken without changing a screenshot (#118). The workflow also asserts the marker still appears in `CIAniListClient.cs`, so renaming the fixture cannot leave the gate grepping for a string nothing emits.
- `CIAiringNotificationService` (`src/AniSprinkles/Services/CI/`) — all methods are no-ops; `RequestPermissionAsync` returns `true`
- `UpdateUser` **echoes the request back into the stub viewer**, the way the real mutation returns the updated user. Returning the untouched static viewer made every Display Preferences change revert on the next Settings load, so that whole section was unverifiable in a CI build (found while verifying #130). `DisplayAdultContent` is deliberately excluded — the canary above depends on the stub viewer reporting the toggle off, and that gate must not be flippable from inside the app.

These stubs are **compiled out entirely** in standard Debug and Release builds.

## Fault Injection (runtime, no rebuild)

Every **Debug** build compiles in fault injection, **disarmed**. It is armed over adb against the
running app, so changing what fails costs a broadcast rather than a ~3 minute rebuild (#125). It
replaced the `-p:ErrorSim=true` flag, which no longer exists.

```powershell
pwsh .claude/skills/run-anisprinkles/driver.ps1 fault GetStudio NotFound next          # client layer
pwsh .claude/skills/run-anisprinkles/driver.ps1 fault Studio NotFound next -layer http # same op, wire name
pwsh .claude/skills/run-anisprinkles/driver.ps1 fault any delay next -delay 4000
pwsh .claude/skills/run-anisprinkles/driver.ps1 fault clear
```

- **It decorates `IAniListClient` rather than replacing it**, so it *composes with the CI stubs*: a
  real screen loads from the fixtures and then the next call breaks. `ErrorSim` failed every call, so
  the screen whose error state you wanted was unreachable — which is why the details pages' error and
  retry states had never been seen on a device.
- **Deterministic scopes only** — `next`, `always`, `firstn:N`, `everynth:N`. No randomness: a fault
  you cannot re-run is not a fixture.
- **`Delay` is independent of failure.** Latency with no error kind is the only way to open the
  cancellation and interlock windows that #116's defect family lives in.
- **Two seams.** `-layer client` (default) decorates the client and works with CI stubs.
  `-layer http` injects into the `HttpClient` pipeline so `AniListRateLimitHandler`,
  `SendAsync`'s retry-once and `AniListErrorClassifier` all run for real — that one needs a real
  signed-in session and does **not** work with `-p:CiBuild=true`.
- **`op` means a different thing per layer, and a miss is silent.** At `client` it is the
  `IAniListClient` method name (`GetStudio`); at `http` it is the GraphQL `operationName`
  (`Studio`) — that is all the handler can see in the request body. They do not reduce to one
  another: `GetMediaListAsync` is `MediaListCollection` over the wire and `SearchMediaPageAsync`
  is `Search`, so no `Get`/`Load`/`Async` stripping would unify them and none is attempted. A
  targeted http profile that misses logs `FAULT http no match` with the operation it actually saw.
- **A profile fires at one layer only.** Both seams share one `FaultState`; without the layer tag a
  single armed profile would fire twice for one logical call.
- Everything is behind `#if DEBUG`, including the exported `BroadcastReceiver`, so none of it can
  reach a Release build — hence no Release guard target, unlike `-p:CiBuild=true`.

See `DEVELOPER_NOTES.md` for the scenario recipes and `/run-anisprinkles` for the driver verbs.

## Build Quality

The project must build with **zero warnings**, and warnings are fixed rather than suppressed — `#pragma warning disable`, `#nullable disable` and the null-forgiving `!` all need explicit sign-off from the repo owner before they go in, not a comment justifying them afterwards. Do not introduce new warnings; fix any that appear before committing. CA1822 ("member can be static") is suppressed project-wide in `.editorconfig` — MAUI `{Binding}` requires instance members even when they only read static state, so the analyzer produces false positives.

**"Zero warnings" means every project, and the test project is the one that gets missed.** Building `src/AniSprinkles/AniSprinkles.csproj` does not compile `tests/`, and `dotnet test` output filtered for failures hides warnings entirely — which is how 15 `xUnit1051` warnings reached a PR while the app builds were reported clean. `xUnit1051` in particular fires on any `await` of a method taking a `CancellationToken`: pass `TestContext.Current.CancellationToken`. Check all four before pushing:

```powershell
dotnet build tests/AniSprinkles.UnitTests/AniSprinkles.UnitTests.csproj -c Debug
dotnet build src/AniSprinkles.Core/AniSprinkles.Core.csproj -c Debug
dotnet build src/AniSprinkles/AniSprinkles.csproj -c Debug -f net10.0-android
dotnet build src/AniSprinkles/AniSprinkles.csproj -c Debug -f net10.0-android -p:EmbedAssembliesIntoApk=true -p:CiBuild=true
```

**A green local suite is not a green suite.** Test classes writing to the process-wide `AppSettings` statics share one collection, so failures that depend on *ordering within* it surface on CI and not here — #128's pending-upstream markers leaked between tests exactly that way, passing locally every run. `TestDataBuilder.ResetAppSettings()` goes through `AppSettings.Clear()` so those markers reset; **new process-wide state must be reset there too**, or it poisons whichever test happens to run next.

## Project Conventions

- **MAUI-first guidance**: do not mix WPF/Xamarin.Forms/Blazor/React patterns unless explicitly requested. Verify MAUI APIs against official Microsoft docs and current project code before recommending.
- **Logging**: `ILogger<T>` injected via DI is the canonical path for all app code. Use structured messages. Bearer tokens are always redacted.
  - Provider wiring lives in `MauiProgram.cs`. `FileLoggerProvider` runs in both Debug (1 MB × 3 at `LogLevel.Debug`) and Release (256 KB × 3 at `LogLevel.Warning`). `AndroidLogcatLoggerProvider` bridges ILogger output into `adb logcat` on Android in all build configs (`AddDebug()` does not reach logcat on .NET MAUI Android). `AddDebug()` stays Debug-only.
  - Exception: `Platforms/Android/MainActivity.cs` and `Platforms/Android/AiringCheckWorker.cs` call `Android.Util.Log` directly because they run before the MAUI DI container is guaranteed to be built (activity lifecycle callbacks; post-reboot WorkManager). Inline comments document this at the call sites. Do not introduce new direct-`Android.Util.Log` callers elsewhere — use ILogger.
  - On-device log file: `{AppDataDirectory}/logs/anisprinkles.log` (+ `.1`, `.2` archives). Pull via `adb shell run-as com.RainbowSprinkles.AniSprinkles cat files/logs/anisprinkles.log` or use `/ani-debug`.
  - **`DiagnosticsLogBuffer` is a third provider, in memory, at `LogLevel.Information` in every config (#112).** It exists because the file log drops `Information` in Release, which is every trace worth sending — no `NAVTRACE`, no `PageState`, no `HTTP`. It keeps roughly the last five minutes, bounded by age *and* entry count, and touches no disk. `DiagnosticsSessionFlusher` writes a snapshot to `{AppDataDirectory}/logs/previous-session.log` from the three global exception handlers and `MainActivity.OnPause`, and clears it again on resume — but only when this process wrote it, since a file left by a process that actually died is the thing worth sending. If you change `DiagnosticsLogBuffer.DefaultRetention`, the popup's "5 minutes" copy is a lie; `DiagnosticsDisclosureTests` fails on purpose when they drift. Neither the ring nor `previous-session.log` is cleared on sign-out — a crash spanning sign-out/sign-in is worth reporting, and this is a single-user install. Revisit before first public release.
- **Telemetry**: Sentry crash reporting only (`SendDefaultPii = false`, `TracesSampleRate = 0.0`, plus a `BeforeSend` redaction pass — `SendDefaultPii` governs IP/username, not message content). Use `ErrorReportService.Record()` for handled exceptions.
  - **The Sentry event comes from `Record`'s `LogError`, not its `CaptureException`** — confirmed by the `mechanism: SentryLogger` tag on the events. `MinimumEventLevel` defaults to `Error`, so the `ILogger` integration captures first and gets the real id; the explicit `CaptureException` on the next line is then dropped by `DuplicateEventDetectionEventProcessor` (`DeduplicateMode` defaults to `All ^ InnerException`, which still includes `SameExceptionInstance`) and returns `SentryId.Empty`. Worse, `Hub.CaptureEvent` assigns `scope.LastEventId = id` unguarded, so that empty id **overwrites** the good one — which is why `SentrySdk.LastEventId` is also empty. Don't build anything on either value; correlate on exception text and timestamp. Do not "fix" it by swapping the two lines either: the logger-created event is the richer one (it carries the `Context` tag, the logger name and a readable message), and a bare `CaptureException` event has none of that. Cost this out before touching it — #112 tried twice and removed the feature instead.
- **User prefs**: `AppSettings` (static, `Utilities/`) persists title language, score format, adult content toggle, and section order through the injectable `AppSettings.Storage` seam, which defaults to `Preferences.Default` (#121). `DisplayAdultContent` commits the instant the Settings toggle flips via `SetDisplayAdultContent`, ahead of the debounced AniList save (#118) — every browse surface filters on it and only re-checks when it appears, so a late commit left 18+ results on screen. Paging must be pinned to the value its page 1 was seeded under (`_seededDisplayAdult` in `SearchPageModel`, `DiscoverPageModel` and `MediaBrowsePageModel`; passed into `DiscoverSectionFetch.PageAsync`) rather than re-reading the static per page, or one result set can hold two policies. All four surfaces — Library included — compare it against the value their current data was built with. Title language and score format commit the same way, via `SetTitleLanguage` / `SetScoreFormat` (#128); before that they reached `AppSettings` only once a save had succeeded. A locally committed change outranks the server's copy until the server reports that same value back — for all three now, not just the adult toggle — so neither a refresh elsewhere in the app nor a return to Settings can sync the pre-change value over it; `SettingsPage.OnDisappearing` flushes any pending save so the server catches up promptly. The settings the Settings page holds on its own (staff name language, restrict-messages, activity merge time, airing notifications, and the per-type notification toggles) carry the same markers there — the per-type ones as a set of unconfirmed types, so a change made on another device still arrives for every type the user did not touch. `AnimeSectionOrder` deliberately has none — there is no control for it, so it can only come from the server.
- **The airing job follows the toggle both ways.** `PopulateFromUser` schedules the WorkManager check when airing notifications land on, and cancels it when they land off. Only the enabling half was wired originally, so turning the setting off anywhere else — the AniList website, another device — left this device still scheduled, and the switch read off while notifications kept arriving. Cancelling an unscheduled job is a no-op, so the else-branch is safe on every load.
- **Pushed detail pages get no lifecycle on a tab return.** `OnAppearing` / `OnDisappearing` fire on tab-*root* pages (Library, Discover, Search, Settings) when you switch tabs, but **not** on a page pushed onto a backgrounded tab's navigation stack — the four detail pages and View All (`AppShell.xaml.cs:23-27`). Verified on device: `MediaDetailsPage.OnAppearing` logged exactly once, at the initial navigation, and tabbing away and back produced nothing. **Use `OnNavigatedTo` instead** — it fires on every tab return, and pairs with `OnNavigatedFrom` on the way out; all five pushed pages call `ViewModel.RefreshDisplaySettings()` from it. Confirmed in the same device run: `OnAppearing` 1, `OnDisappearing` 0, `OnNavigatedTo` 3 across two tab round-trips. No unit test will tell you which to use — the page model behaves correctly when called, and the bug is that nothing calls it, so a test driving the page model directly passes while the feature is dead on device. Verify on device via `/run-anisprinkles`, and see #131.
- **`ConfigureAwait(true)` in page models is deliberate.** It is the default, so it changes nothing at runtime — it states that the continuation writes bound state and must stay on the UI thread. `DetailsPageModelBase`, `PaginatedSection`, `MediaBrowsePageModel`, `ListOperationRunner` and `SettingsPageModel` all mark their data-fetch awaits this way. A `ConfigureAwait(false)` inside `AniListClient` governs continuations *inside that method* and does not propagate to the caller, so a page-model await resumes wherever its caller was — which is the UI thread for every lifecycle and command entry point. Don't add `ConfigureAwait(false)` to a page-model await whose continuation touches an `[ObservableProperty]` or a bound `ObservableCollection`.
- **Failed settings saves**: dirty-tracking is baselined against what the *server* reported, not the resolved local value, so a change that never landed leaves the page dirty and the next flush re-sends it (#128). A successful `UpdateUser` clears the markers for the values it actually carried — compared field by field, since the user can change a setting while a save is in flight, and clearing that one would discard a change the server never saw. A save arriving while another is in flight is coalesced into a second pass rather than dropped, and the failure snackbar goes through `ShowFailureSnackbarAsync` so a `ServiceOutage` offers no Retry.
- **Display settings and already-rendered pages**: title language and score format feed computed properties (`Media.DisplayTitle`, `MediaListEntry.ScoreDisplay`, the details rating control), so a change has to re-render what is already on screen. Each surface snapshots a `DisplaySettingsSnapshot` and re-projects in its appearing path when it moved — **never a refetch**, which would spend an AniList request on a formatting change (#127). `Media` and `RelatedMedia` are plain classes and cannot raise `PropertyChanged`, so the observable containers implement `IDisplayProjection` and re-raise the property carrying them (`Media` / `Node`), which makes MAUI re-resolve the nested binding path. A new carousel item type that shows a media title must implement it, or its cards render stale titles forever with nothing to catch it. Title language also moves the Title **sort order**, since `MediaListSection` sorts by `DisplayTitle`.

## Working with AI Agents

### Commits and pushes

Do not commit or push unless explicitly asked (e.g. "commit this", "push it"). The exception is when asked to create a PR — that implies doing everything needed: branch, commits, push, and PR creation.

### Self-review

After writing code, run through the review checklist in `.claude/skills/ani-review/SKILL.md` (`/ani-review`). Fix all issues found before presenting. The review loop is internal — do not surface bugs as a list of things found.

### PR feedback review

When asked to pull PR feedback, use `.claude/skills/ani-pr-feedback/SKILL.md` (`/ani-pr-feedback`).

### Presenting options

When presenting 2+ approaches to the user, list them clearly with tradeoffs for each. Do not just pick one and proceed without asking. If your client supports a popup/question UI (e.g. `AskUserQuestion`, `vscode_askQuestions`), use it instead of listing options in plain text.

### Output style

- No AI attribution or agent branding anywhere in generated project artifacts. This includes branch names, commit messages, PR titles, PR descriptions, issue bodies, comments, release notes, and footers. Avoid labels such as "codex", "Claude", "Copilot", "AI-generated", or similar unless the user explicitly asks for them.
- Be terse. Skip pleasantries and preamble.

## Security

- **OAuth implicit grant** via `WebAuthenticator`; tokens stored in `SecureStorage`, never logged.
- Bearer tokens are redacted **at the source**, not at each sink (#124). `SensitiveText.Redact` is applied in `AniListClient` to every server-derived string that becomes an exception message, so the token never enters the exception and the file log, logcat and Sentry are safe by construction. `SentryScrubber` (wired via `options.SetBeforeSend`) is the backstop for exceptions Sentry captures without going through `ErrorReportService`. Classification runs on the raw text and redaction only on what gets stored, so `AniListErrorClassifier` keeps matching "Invalid token" and the outage markers.
- **`SentryScrubber` does not walk attachments**, so it is *not* the backstop for a user-sent diagnostic report (#112) — that report goes to Sentry as an attachment, by a route `SetBeforeSend` never inspects. `DiagnosticsReportBuilder.Build` runs one `SensitiveText.Redact` pass over the whole finished report, and `SentryDiagnosticsSink` redacts the free-text description separately because it takes a third route again (`SentryFeedback`). If you add a section to that report, it inherits the pass; if you add another *sink*, it does not.
- Sentry: `SendDefaultPii = false`. AniList Client ID (`35674`) is a public app identifier, not a secret.
- Sign-out clears both in-memory token fields and both SecureStorage keys.
- Token expiry is tracked and auto-cleared when expired (`IsExpired()` check on access).
